# WSL 管理器

这是一个 WSL 管理器 GUI 软件，目标是让 WSL 发行版可以被像本机服务一样长期、可观测、可恢复地运行和管理。

## 产品目标

- 能查看 WSL 发行版列表，对发行版进行基本操作，例如启动、停止、关闭全部。
- 能查看运行中的 WSL 实例及其状态，并对状态进行统计。
- 实现 WSL 保活。传统保活机制通常需要命令行持续运行命令，本软件需要提供多种保活机制，以尽量降低对 Host 的影响，使 WSL 能作为服务使用。
- 提供保活设置、保活状态统计、失败提示和操作日志。
- 必要时配合容器内部的脚本、应用或服务里应外合，以获得更准确的健康状态和更低成本的保活能力。

## 技术栈要求

- .NET 10 / C#
- Avalonia 12 / Huskui.Avalonia
- 其他技术自选，只要能达成目的即可。

## 功能要求

### 1. 基础实例管理

- 查看所有 WSL 发行版。
- 显示发行版名称、默认标记、运行状态、WSL 版本。
- 支持启动选中的发行版。
- 支持停止选中的发行版。
- 支持关闭全部 WSL 实例。
- 支持查看 `wsl.exe --status` 等主机侧状态信息。
- 提供运行中数量、停止数量、保活中数量等汇总统计。

### 2. 后台运行与托盘控制

- 程序支持后台运行。
- 点击主窗口关闭按钮时只隐藏主窗口，不退出程序。
- 托盘图标支持重新打开主界面。
- 托盘菜单至少包含：打开主界面、隐藏主界面、退出。
- 只有显式退出时才停止保活任务并释放相关资源。
- 托盘 tooltip 应显示关键状态，例如运行中实例数、保活实例数、最近错误。

### 3. 开机自启动

- 支持配置开机自启动。
- 支持启动时自动最小化到托盘。
- 支持用户在界面中开启或关闭自启动。
- 自启动配置应避免重复写入，并能正确清理。

### 4. 保活策略

- 支持多种保活策略：
  - 周期心跳：按指定间隔向目标发行版发送轻量命令。
  - 驻留进程：在目标发行版内启动低成本驻留进程。
  - 容器内 Helper：通过发行版内安装的 helper 脚本进行低成本心跳、状态采集和健康检查。
- 支持为每个发行版独立配置保活策略。
- 支持保活间隔、是否自动启用、失败重试策略等设置。
- 支持查看每个保活策略的状态、最近心跳时间、成功次数、失败次数、最近错误。
- 保活策略需要尽量降低 Host 和 WSL 内部资源开销。

### 5. 保活策略持久化

- 保存每个发行版的保活配置。
- 保存全局设置，例如是否开机自启动、是否启动到托盘、默认心跳间隔。
- 程序启动后自动加载配置。
- 对启用了自动恢复的发行版，程序启动后自动恢复保活策略。
- 配置文件应使用结构化格式，例如 JSON。
- 配置文件需要考虑发行版被删除、重命名或不可用时的降级行为。

### 6. 失败通知与日志

- 保活失败时应记录日志。
- 驻留进程异常退出时应记录日志。
- WSL 命令执行失败时应记录命令、退出码和错误信息。
- 关键失败应通过托盘或系统通知提示用户。
- 日志面板应支持查看操作历史、保活心跳、错误原因和时间。
- 日志应限制大小，避免长期运行无限增长。

### 7. 实例资源与运行状态

- 展示每个 WSL 实例的轻量状态指标：
  - uptime
  - 进程数
  - 内存占用
  - 负载或 CPU 概况
  - 主要服务状态
- 状态采集应允许失败，并在界面上展示不可用原因。
- 采集频率应可配置，避免对 Host 和 WSL 造成明显负担。

### 8. 服务健康检查

- 用户可以为每个发行版配置健康检查。
- 健康检查类型至少支持：
  - 自定义 shell 命令。
  - TCP 端口检查。
  - systemd service 状态检查。
- 健康检查结果应显示为健康、异常、未知。
- 健康检查失败时应支持通知和日志记录。
- 健康检查应可与保活策略联动，例如失败后重启发行版或重新启动保活策略。

### 9. 容器内 Helper

- 提供一键安装 helper 到指定发行版的能力。
- Helper 可用于：
  - 上报 uptime、负载、内存、进程数。
  - 执行低成本心跳。
  - 检查 systemd service。
  - 执行健康检查命令。
  - 返回结构化状态数据。
- Helper 需要有版本号。
- GUI 应能检测 helper 是否安装、版本是否匹配、是否需要更新。
- Helper 安装和更新过程需要有日志与错误反馈。

### 10. 快速入口

- 对选中发行版提供快速入口：
  - 打开 Windows Terminal。
  - 打开发行版 home 目录。
  - 打开发行版根目录。
  - 复制 `\\wsl$\<发行版>` UNC 路径。
- 快速入口失败时应给出明确错误信息。

### 11. 导入、导出与备份

- 支持通过 GUI 调用 `wsl --export` 备份发行版。
- 支持通过 GUI 调用 `wsl --import` 导入发行版。
- 支持危险操作保护，例如 `wsl --unregister` 前必须二次确认。
- 导入导出任务应展示进度或至少展示执行状态。
- 长任务应避免阻塞 UI。

## 阶段化实现目标

### 阶段 1：基础可用版本

目标：形成一个可以日常使用的 WSL GUI 管理器。

- 创建 .NET 10 / Avalonia 12 / Huskui.Avalonia 桌面应用。
- 实现 WSL 发行版列表读取。
- 实现启动、停止、关闭全部。
- 显示 WSL 主机状态。
- 显示基础统计：总数、运行中、已停止、保活中。
- 实现周期心跳保活。
- 实现驻留进程保活。
- 支持后台运行和托盘菜单。
- 支持单文件自包含发布脚本。

### 阶段 2：服务化体验

目标：让用户可以把 WSL 当作长期服务来使用。

- 实现开机自启动。
- 实现启动时最小化到托盘。
- 实现全局设置持久化。
- 实现每个发行版的保活策略持久化。
- 程序启动后自动恢复已启用的保活策略。
- 托盘 tooltip 显示关键运行状态。
- 保活失败时显示托盘或系统通知。

### 阶段 3：可观测性

目标：让用户能判断 WSL 和内部服务是否真的可用。

- 实现日志面板。
- 记录用户操作、WSL 命令、保活心跳、失败原因。
- 限制日志大小并支持清理。
- 展示实例 uptime、进程数、内存占用、负载等轻量指标。
- 支持配置状态采集间隔。
- 展示最近错误和健康摘要。

### 阶段 4：容器内 Helper 与健康检查

目标：通过里应外合提升状态准确性和保活效率。

- 设计 helper 脚本协议和版本机制。
- 实现一键安装、检测、更新 helper。
- Helper 返回结构化状态数据。
- 支持自定义命令健康检查。
- 支持 TCP 端口健康检查。
- 支持 systemd service 健康检查。
- 健康检查失败时支持通知、日志和策略联动。

### 阶段 5：运维增强能力

目标：覆盖用户高频管理动作和备份恢复场景。

- 实现打开 Windows Terminal。
- 实现打开 WSL home 或根目录。
- 实现复制 UNC 路径。
- 实现发行版导出备份。
- 实现发行版导入恢复。
- 实现危险操作保护，例如注销发行版前二次确认。
- 长任务支持后台执行和状态反馈。

## 非功能要求

- UI 不应被 WSL 命令阻塞。
- 后台任务应可取消，并在程序退出时可靠清理。
- 保活机制应尽量低资源占用。
- 失败信息应对普通用户可理解，对开发者可排查。
- 所有危险操作必须有明确确认。
- 配置和日志应保存在用户目录下，避免依赖程序安装目录可写。
- 发布产物应支持自包含单文件可执行程序。
